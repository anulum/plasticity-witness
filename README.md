# Plasticity Witness

Plasticity Witness is being built to compare learning-rule updates against an independent reference, preserving the actual rule, numerical realization, complete stimulus and observed state. This checkout contains repository validation tooling and documentation. Full foundation qualification is in progress. There is no installed learning-rule comparison package, plasticity runner, public plasticity-analysis command or qualified learning report.

## Boundary

This project owns the intended independent oracle, protocol population, update or supported distributional comparison and learning report. SC-NeuroCore retains the implementations under test. Loop Timing Witness owns capture and timebase; Evidence Manifest Toolkit supplies shared evidence operations. SC Stream Prover and Randomness Witness supply separately qualified arithmetic and source evidence when a distributional comparison requires them.

A matching scalar weight does not establish matching state, random stream or update history. Software, RTL and measured fabric are separate evidence scopes. A conditioned learning comparison does not establish reliability rates.

## Current tooling

Seven repository controls inspect metadata, source attribution, workflows, dependency alignment, native documentation, inventory and preflight orchestration. Native-tool bootstrap checks selected development executable and licence bytes. Domain capabilities, claims and qualified formats remain empty at architecture-only maturity.

Use the exact environment in [Contributing](CONTRIBUTING.md). Named commands are make metadata, make source-provenance, make workflows, make dependencies, make docs, make inventory and make licence. Full CI/preflight belongs in CI or an explicitly admitted pre-push environment. See [Validation](VALIDATION.md) for the scope.

## Intended evidence

A report will bind the source rule, independent oracle reference, full pairing, rate, applicable triplet or reward protocol, numerical operation schedule, conditions and complete observation population. Every required unavailable state or capture remains visible. Bit-exact and distributional lanes require different evidence. The planned report format is neither registered nor qualified here.
